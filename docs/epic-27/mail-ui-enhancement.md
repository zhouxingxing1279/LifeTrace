# EPIC-27 邮件列表与阅读体验优化

## 目标

在不改变现有 IMAP/SMTP 同步核心的前提下，将邮件模块从三栏“行动中心”调整为更接近桌面邮箱的列表式浏览体验，并保留 LifeTrace 的手动行动转换能力。

## 已确认需求

1. 邮箱首页只展示最近 30 天已同步的收件箱邮件，不在首页展开正文。
2. 首次同步仍保持最近 30 天范围，后续继续按 UID 增量同步；不做全量历史邮箱回填。
3. 同一发件人按邮箱地址聚合。聚合项在首页只占一条记录，并显示聚合内邮件数量、最新一封标题和最新时间。
4. 单封邮件不做额外聚合，首页直接显示为一条邮件记录。
5. 点击聚合项进入该发件人的邮件列表；右键聚合项也直接进入该列表，不弹出额外上下文菜单。
6. 发件人邮件列表中一条对应一封邮件，按接收时间倒序排列。
7. 点击具体邮件后切换到独立邮件详情界面，而不是在当前列表中展开正文。
8. 邮件详情左上角提供返回按钮，并返回进入详情前的列表（收件箱或发件人聚合列表）。
9. 邮件详情展示主题、发件人、收件人、时间、完整正文、附件和现有的手动操作（已读/未读、归档、回复、转任务/日历/Memo/等待事项）。
10. HTML 正文继续使用服务端已清洗内容；正文中的 HTTP/HTTPS/mailto 链接可点击，危险协议不得执行。纯文本正文中的 HTTP/HTTPS 链接也应可点击。
11. 邮件列表使用轻量消息摘要 API，不返回完整正文；API 支持分页，前端加载完整的 30 天摘要集合后再做精确的发件人聚合，避免原先 200 个 thread 上限导致较早邮件不可见。
12. 126 邮箱此前的网易 IMAP `Unsafe Login` / `ID` 兼容问题已经解决，本任务不重复修改该问题。

## 验收标准

- 首页不存在邮件正文展开区域。
- 同发件人 N 封邮件首页显示为 1 条，并明确显示 `N 封`。
- 聚合项点击/右键后进入该发件人的邮件列表。
- 单封邮件点击后进入独立详情界面，左上角返回可恢复上一级列表。
- 详情正文链接可以安全点击。
- 30 天内邮件数量超过单页限制时仍能完整纳入首页聚合结果。
- `npm run lint`、相关前端构建/单测、Cloud Rust tests/clippy 及现有正式 CI 全部通过后方可合并 `main`。

## 执行状态

实现已完成并与当前 `main` 基线同步。网易 IMAP 兼容实现保持不变，仅将对应 Rust 测试模块移动到生产项之后以满足 `clippy --all-targets -D warnings`；该 clippy 修复已单独验证通过。

最终仍以当前 HEAD 的 Browser Web、EPIC-05 Windows Sync、EPIC-03 PostgreSQL 三套正式工作流全部成功作为合并门禁。

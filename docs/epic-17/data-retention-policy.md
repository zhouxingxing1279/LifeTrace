# LifeTrace 数据保留与删除策略

> 版本：1  
> 日期：2026-08-10  
> 适用范围：LifeTrace Cloud、Windows/Desktop、Browser Client 及后续移动客户端

## 1. 原则

LifeTrace 采用本地优先和最小必要保留原则。业务功能不需要的数据不应因为“以后可能有用”而无限期保留；密码、Token、Cookie、第三方凭据和完整敏感正文不得进入普通诊断日志。

## 2. 在线业务数据

账号存续期间，用户业务数据按功能需要保留。用户删除单条业务记录时按对应领域的删除/墓碑规则处理；用户注销账号时，Cloud 在线业务副本通过 `cloud_users` 用户锚点在单个数据库事务中级联删除。

账号注销包括：

- 用户账号在线记录；
- 设备与应用授权；
- Session、Access/Refresh Token 数据；
- 同步实体、变更和 Snapshot；
- 邮件账号元数据、文件夹、邮件、草稿、发件队列等 Cloud 专属业务数据；
- 其他通过用户外键归属到账号的数据。

安全审计允许保留最小、非内容型事件元数据，但必须解除 user/session/device 的直接标识关联，并不得保留密码、Token、Cookie、邮件正文、健康正文或第三方凭据。

## 3. Session 与 Token

- Session 和 Token 仅在配置的有效期内可用。
- 主动退出、撤销设备、全局退出或账号注销后立即不可用。
- 账号注销时相应数据库记录随用户级联清理。
- Token 原文不得写入数据库普通业务列或普通日志。

## 4. 通知原文

通知原文只在实现用户可见功能确有必要时保留，并遵循：

1. 优先提取金额、商户、时间、状态等结构化字段。
2. 业务不再需要原文后应删除原文，仅保留派生字段。
3. 普通日志不得记录完整通知正文。
4. 后续 Android 自动记账实现必须提供可见的保留说明和清理入口。

## 5. 导入文件

账单、训练结果、OCR、邮件附件等导入证据必须：

- 有明确用户归属；
- 在 UI 中可定位其来源和用途；
- 支持用户主动删除；
- 不允许无说明无限期保留；
- 元数据删除与文件对象删除保持一致。

当前 Cloud 尚未把 EPIC-12 对象存储作为生产依赖，因此 EPIC-17 注销逻辑在检测到非空外部 `storage_ref` 时会 fail closed：在外部对象删除能力真正成功前，不报告账号删除成功。这样可以避免数据库记录删除后留下无法追踪的外部对象。

## 6. 诊断日志

诊断日志遵循 EPIC-19 的轮转、大小限制和保留配置，并执行二次脱敏。以下内容禁止进入普通日志：

- Access Token / Refresh Token；
- `Authorization` Header；
- Cookie / Session Secret / CSRF Secret；
- 密码及 password hash；
- 邮箱授权码、API Key、第三方凭据；
- 完整邮件正文；
- 完整健康数据正文；
- 加密相册密钥或可直接恢复私密内容的材料。

调试日志也不豁免上述规则。生产环境默认不得依赖 debug 日志才能正确运行。

## 7. 备份

Cloud 在线删除与历史备份采用不同生命周期：

- 账号注销后，在线数据库立即执行事务性删除。
- 已生成的加密备份不做原地重写，以避免破坏备份完整性。
- 历史备份在配置的保留窗口到期后自然淘汰。
- 恢复流程必须识别已注销账号状态，不能因为恢复旧备份而把已删除账号重新投入在线服务。
- 备份保留窗口、加密方式和恢复演练由 EPIC-15 的部署配置落实。

## 8. 用户数据导出

`GET /api/v1/privacy/export` 提供机器可读 JSON 导出，并支持模块白名单筛选。导出包括用户业务数据和必要账号元数据，但明确排除：

- password hash；
- Access/Refresh Token；
- Session Secret；
- 邮件 credential ciphertext / nonce；
- 服务端 Secret 和签名密钥。

导出接口本身必须要求认证，且不得把导出正文复制到普通日志。

## 9. 账号注销

`DELETE /api/v1/privacy/account` 是高风险操作，必须：

1. 使用有效认证身份；
2. 提交精确确认短语 `DELETE MY ACCOUNT`；
3. 在事务内验证是否存在尚未能删除的外部对象；
4. 外部对象无法保证删除时 fail closed；
5. 清理在线业务数据、Session 和 Token；
6. 仅返回删除摘要，不返回已删除的敏感正文。

## 10. 后续依赖

EPIC-12 正式对象存储上线后，需要把对象存储删除器接入注销事务的编排流程；EPIC-15 需要把实际生产备份窗口、恢复演练和已注销账号恢复抑制机制纳入持续验证。本策略定义安全边界，这两个 Epic 提供对应基础设施实现。

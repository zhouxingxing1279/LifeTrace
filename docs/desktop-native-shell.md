# LifeTrace 桌面端交互架构

## 目标

桌面端与 Web 端共享业务能力、云端数据契约和路由内容，但不共享应用外壳。桌面端应优先利用大屏、持续运行、本地文件、SQLite、副本同步和系统级快捷操作等能力。

## 架构边界

- Web：保留自己的 `AppShell`、响应式导航和浏览器交互。
- Desktop：使用 `DesktopWorkbenchShell` 作为唯一桌面外壳。
- Shared：继续复用 `RouteView`、云端数据模型、API 契约和页面业务组件。
- Native：本地照片、SQLite、账单导入等能力通过“本机工具”进入，不再使用“云端功能 / 本地功能”悬浮二选一。

## 桌面信息架构

1. 左侧常驻导航：面向长期模块跳转，支持收起为图标栏。
2. 顶部命令栏：后退、前进、当前模块信息、同步状态、隐私模式和辅助面板开关。
3. 中央工作区：渲染共享业务内容，不再嵌套 Web `AppShell`。
4. 右侧辅助面板：同步状态、快捷开始和桌面原生能力入口。
5. 本机工具：作为桌面原生能力层存在；离线时自动成为可用入口，而不是另一套产品导航。

## 回归约束

`browser-desktop-parity.test.ts` 必须保证：

- Desktop 仍复用 `RouteView`，避免复制业务功能。
- Desktop 不导入 Web `AppShell`。
- 不恢复 `lt-desktop-workspace-switch` 或“云端功能 / 本地功能”双工作区切换。
- 桌面外壳必须保留命令栏、辅助面板和本机工具入口。

# LifeTrace 二期产品与开发路线图

> 启动日期：2026-08-12  
> 状态：规划中  
> 用途：承接 LifeTrace 一期基础架构、多端同步和核心业务能力之后的产品深化工作。二期不以继续堆叠模块为目标，而是优先把已经存在的能力重构为可长期使用、可持续积累数据、具有完整业务闭环的个人管理系统。  
> 组织方式：二期继续以 Epic 为最高一级规划单元；每个 Epic 先明确产品目标、范围、边界、依赖与验收标准，执行阶段再拆分 implementation plan、execution plan 和具体 Issue。

---

## 1. 二期总体目标

LifeTrace 二期的核心方向从“把主要模块做出来”转向：

> **让已有模块真正形成长期使用闭环，并围绕个人数据积累持续提高使用价值。**

二期规划遵循以下原则：

- 优先深化已经存在且具有长期价值的功能，不为数量继续增加孤立模块。
- 继续坚持本地优先、离线可用和多端可同步。
- 业务数据必须形成长期可积累的正式领域模型，而不是只停留在页面状态或临时 JSON。
- AI 只用于确实需要语言理解、生成或分析的场景，不用 AI 替代可以确定性实现的功能。
- 优先建设“计划 → 执行 → 记录 → 复习/反馈 → 长期统计”的闭环。
- 桌面端承担深度整理、学习和分析；移动端承担快速进入、轻量执行和随手记录。
- 二期 Epic 可以独立开发和验收，但应继续复用一期统一领域服务、同步协议、账号体系和基础设施。

# EPIC-33：英语学习闭环 2.0

## 目标

LifeTrace 当前英语模块已经具备每日文章、文章库、阅读状态、原文音频、高亮、快捷笔记、划词词典、翻译、生词本、间隔复习、英文总结、AI 反馈和历史统计等基础能力。

二期不再以增加零散页面为主要方向，而是将这些能力重新组织为完整学习闭环：

```text
今日学习计划
    ↓
阅读 / 精听 / 词汇复习 / 口语任务
    ↓
生词、句子、高亮和笔记沉淀
    ↓
间隔复习
    ↓
理解、自我反馈和可选 AI 分析
    ↓
长期能力与学习时间统计
    ↓
生成下一阶段学习任务
```

最终使英语模块从“英文阅读器 + 生词本”演进为 LifeTrace 内的个人英语学习系统。

---

## 产品范围

### 1. 今日学习队列

将当前以“今日文章”为中心的首页升级为以“今日学习任务”为中心。

每日任务可由以下内容组合：

- 到期词汇复习
- 到期句子复习
- 当日阅读任务
- 未完成文章续读
- 精听任务
- 口语训练任务
- 轻量理解或总结任务

支持根据用户可用学习时间组织任务，并展示预计耗时、完成状态和当日总进度。

目标是让用户打开英语模块后不再自己决定“今天学什么”，而是直接进入当天最需要完成的训练。

### 2. 词汇复习升级

保留当前生词来源、释义、上下文、词频、出现次数和复习日志等能力，将复习调度升级为更成熟的间隔重复模型。

规划方向：

- 使用 FSRS 或等价的现代间隔重复调度模型。
- 保留 Again / Hard / Good / Easy 四级反馈。
- 根据实际复习结果动态计算下一次复习时间。
- 区分新词、学习中、复习中、已掌握和归档状态。
- 继续记录来源文章和来源句子。
- 支持同一单词在不同材料中再次出现时累计 encounter 信息。

不再依赖简单固定阶段作为主要调度逻辑。

### 3. 精听学习模式

在现有文章来源音频基础上增加真正适合语言学习的精听播放器。

核心能力：

- 音频与文本分段关联
- 上一句 / 下一句
- 单句循环
- A-B Repeat
- 播放速度调整
- 自动暂停
- 字幕显示 / 隐藏
- 键盘快捷操作
- 从当前句直接查词、收藏句子或添加笔记

优先利用已有字幕、文本和官方音频，不以 AI 自动字幕作为二期前置条件。

### 4. 句子学习库

在现有“单词、高亮、笔记”之外新增正式的句子学习实体。

句子可来自：

- 阅读正文
- 精听字幕
- 用户主动收藏
- 后续其他导入材料

句子记录需要保留：

- 原文
- 可选翻译
- 来源材料
- 来源位置
- 可选音频时间段
- 用户笔记
- 标签
- 复习状态

重点用于积累搭配、句型和真实表达，而不是只记孤立单词。

句子后续可进入间隔复习队列。

### 5. 阅读学习闭环

继续保留当前阅读器的高亮、快捷笔记、划词、翻译和阅读状态能力，并进一步与用户个人词库和句子库打通。

规划包括：

- 正文显示个人词汇学习状态。
- 已见过的单词再次出现时累计 encounter。
- 从正文直接加入生词或句子学习库。
- 保留原文上下文，不将学习对象脱离来源材料。
- 阅读完成状态与后续理解任务分离。
- 已完成文章可随时重新打开，并恢复已有标注、笔记和学习状态。

### 6. 阅读理解与输出训练

当前展示型理解问题升级为可交互的阅读后自测。

支持不同训练深度：

- 轻量：完成阅读和必要复习。
- 标准：阅读 + 理解题 + 简短英文输出。
- 深度：精读 + 英文总结 + 可选 AI 反馈。

英文整篇 Summary 不再作为所有文章的强制流程，以降低每日学习阻力。

### 7. 口语训练管理

LifeTrace 二期不自行重复开发完整实时 Voice AI。

口语模块负责：

- 生成或维护每日口语训练任务
- IELTS Speaking 等主题训练计划
- 提供可复制的训练提示词
- 记录口语训练时长
- 记录训练主题
- 记录自我评分
- 标记词汇、流利度、语法、发音等薄弱项
- 保存训练笔记
- 汇总长期口语训练数据

实时自由对话可由 ChatGPT Voice 等成熟外部能力承担，LifeTrace 负责学习计划、记录和复盘。

### 8. 学习资料库

将当前文章库逐步演进为统一英语学习资料库。

资料类型预留：

- Article
- Audio
- Podcast
- Video Transcript
- 用户导入文本

第一阶段继续以现有 VOA 等稳定来源为主，不要求一次性支持所有来源。

统一保留来源、作者、发布时间、版权信息、音频、正文、难度、CEFR 等元数据，为阅读和精听共用。

### 9. 学习统计

统计重点从“完成数量”升级为“长期学习行为和能力变化”。

核心统计包括：

- 每日 / 每周 / 每月英语学习总时长
- 阅读、精听、词汇复习、口语训练的时间分布
- 阅读篇数和材料难度分布
- 新增词汇数量
- 实际复习数量
- 到期积压数量
- 词汇记忆保持情况
- 句子积累和复习情况
- 不同 CEFR 难度材料完成情况
- 连续学习天数
- 口语训练频率和累计时长
- 可选的语法、词汇、结构等长期薄弱项

AI 评分只能作为辅助指标，不作为英语进步的唯一核心指标。

### 10. AI 能力边界

英语模块不直接绑定具体模型厂商。

需要 AI 的能力统一通过 LifeTrace AI Gateway 或统一 Provider 配置调用，例如：

- 英文总结分析
- 句子解释
- 语法解释
- 可选翻译
- 个性化学习建议

确定性能力优先使用本地或普通程序实现，例如：

- 复习调度
- 音频循环
- 字幕定位
- 阅读状态
- 统计
- 查词
- 学习任务调度规则

二期不将以下能力作为核心建设项：

- 自研实时语音大模型
- 自研 ASR/TTS 对话链路
- AI 自动字幕作为必需依赖
- 自研发音评分模型
- 复杂多 Agent 英语老师

## 数据与架构要求

英语二期产生的长期数据必须进入正式领域模型，并具备后续多端同步能力。

重点实体至少包括：

- EnglishLearningRecord
- EnglishMaterial / EnglishArticle
- UserVocabulary
- VocabularyReviewLog
- SavedSentence
- SentenceReviewLog
- SpeakingSession
- EnglishLearningTask
- EnglishHighlight
- EnglishNote

具体 Schema 在实施阶段设计，本规划不提前固定所有字段。

现有桌面端英语组件需要逐步拆分，避免继续将首页、阅读器、文章库、总结、反馈、历史和助手逻辑集中在单个大型组件中。

建议按领域逐步演进为：

```text
english/
├── dashboard/
├── reader/
├── listening/
├── vocabulary/
├── sentences/
├── speaking/
├── materials/
├── statistics/
└── services/
```

该目录仅表示模块边界方向，不作为本 Epic 的硬编码文件结构要求。

二期应优先复用并升级现有实现，不进行无必要的推倒重写。

保留并演进：

- 每日文章
- 文章库
- VOA 原文与音频
- 阅读状态
- 高亮
- 快捷笔记
- 划词词典
- 翻译
- 生词本
- 现有四级复习交互
- 英文总结
- AI 反馈
- 历史学习记录

新增的学习队列、精听、句子库、FSRS 和口语记录需要与这些现有能力形成统一数据闭环。

主要依赖一期已经规划或实现的基础能力：

- 统一领域模型
- 本地 SQLite
- 多端同步协议
- LifeTrace Cloud
- 账号与设备体系
- AI Provider / AI Gateway

英语二期应允许桌面端在云端或移动端尚未完成时先独立运行，不应让同步能力阻塞核心本地学习流程。

## 验收标准

EPIC-33 完成后应满足：

- [ ] 英语首页以每日学习任务而不是单篇文章作为核心入口。
- [ ] 到期词汇能够自动进入当天复习队列。
- [ ] 词汇复习使用动态间隔调度，而不是只使用固定阶段。
- [ ] 文章音频可以进行逐句播放、循环和精听操作。
- [ ] 用户可以从阅读或精听内容保存完整句子并长期管理。
- [ ] 单词、句子、文章、高亮和笔记之间保留来源关系。
- [ ] 阅读理解具有实际交互和完成结果，而不只是展示问题。
- [ ] 支持轻量、标准和深度学习流程，不强制每天写完整英文总结。
- [ ] 可以记录外部 Voice 口语训练的主题、时长和薄弱项。
- [ ] 学习统计能够展示阅读、听力、词汇复习和口语的长期投入。
- [ ] 核心学习流程在无 AI Provider 时仍可使用。
- [ ] AI 能力不直接绑定 DeepSeek、OpenAI 或其他单一厂商。
- [ ] 新增长期学习数据具备进入统一同步体系的领域模型。
- [ ] 桌面端英语模块完成必要的组件边界拆分，后续功能不继续堆积在单一大型组件中。

---

## 暂不纳入本 Epic

以下方向暂不作为 EPIC-33 的验收前置条件：

- 自研实时语音对话模型
- 自研发音评分模型
- 全自动 AI 字幕生成
- 大规模游戏化、积分商城或排行榜
- 一次性支持所有播客和视频网站
- 多 Agent 英语老师
- 用 AI 自动决定并执行所有学习行为

---

## 后续拆分方式

进入执行阶段后，EPIC-33 再进一步拆分为独立实施文档和 Issue。建议实施顺序为：

```text
现有英语模块数据与组件整理
→ 今日学习队列
→ 词汇 FSRS
→ SavedSentence 与句子复习
→ 精听播放器
→ 阅读理解与分级训练流程
→ 口语任务记录
→ 学习统计升级
→ AI Provider 解耦与整体联调
```

该顺序是当前规划建议，实施前可依据现有代码状态和依赖重新调整。
